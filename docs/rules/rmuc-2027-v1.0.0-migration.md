# RMUC 2027 V1.0.0 — 正式规则迁移基线

> 状态：**P0 官方规则差异核对基线，不等于2027完整规则已实现**。本文件记录2026-10-15发布的2027 RMUC规则关键变动、现有仓库的真实耦合点与第一轮迁移验收边界。详细进度请见 [Issue #103](https://github.com/Tyr1onX/tarsgo-simulator/issues/103)。

## 基准与禁忌

- **主规则依据**：《RoboMaster 2027 机甲大师超级对抗赛比赛规则手册 V1.0.0》（2026-10-15），重点 §1.2 / §3～§7。
- **硬件与能力约束**：《RoboMaster 2027 机甲大师高校系列赛机器人制作规范手册 V1.0.0》（2026-10-15），重点 §2.4、§3。
- 《RoboMaster 2027 机甲大师高校联盟赛参赛手册 V1.0.0》是 **RMUL参赛手册**，不可替代 RMUC 比赛规则；机器人制作规范的同名副本并非另一个版本。
- 未提供的2027正式通信协议、后续答疑与标注“待定”的项目**不能猜参数**；如为了演示采用仿真假设，要显式命名和隔离，不得标记为官方规则。
- 2026 RMUC V1.4.0、RMUL、Training 独立可运行，**禁止原地改写旧规则集**。

2. **§5.7.4**：雷达干扰波三档难度的具体参数“后续发布”。
3. 2027正式通信协议和后续规则增补/答疑尚未随本次材料给出；禁止用旧版协议模拟为2027官方精确通信。

## 仓库实证：2026耦合点（以main 3fe45ec为基线）

- `src/tarsgo_simulator/rules/registry.py`：仅注册 `training-v0`、`rmul-2026-3v3`、`rmuc-2026-region-v1.4.0`。
- `src/tarsgo_simulator/rules/rmuc_2026_region.py`：约束旧版英雄、工程、步兵、哨兵与单台射击空中机器人；**保留其2026实现，不改名为2027**。
- `configs/scenarios/rmuc-2026-region-rules-lab.yaml`：固定旧阵容和旧地图，另建2027独立场景而非原地替换。
- `src/tarsgo_simulator/core/match.py`：有 `type == "drone"` 的空中判断、显式2026规则ID判断以及观战AI的旧角色枚举；**先定位真实共享能力，再逐处解除阻碍，不用推倒整体Match**。
- `src/tarsgo_simulator/rules/protocol.py`：显示状态字段包括 `rebuild_opportunities`、`engineer_energy_units`、`drone_air_support`、`radar_anti_drone`；这些旧字段不能默认代表2027功能。
- PR #102 已支持种子与60Hz、420秒重放；新赛季应复用这一设施，不能新建第二套状态及事件总线。

## 启动顺序和 PR 完成标准

1. **P1：独立2027最小规则入口**。定义新规则文档ID、注册独立RuleSet、合法机器人类型/数量与最小场景。若规则不能完整运行，必须明确仍为受限 Rules Lab，不得宣称已完成2027全规则。添加创建、重置、基本时间推进与2026/RMUL/Training回归。
2. **P2：2027控制度与结算闭环**。真实增益点占领、临时/完全控制、占领倒退/暂停、前哨转归、基地防御、累计控制度、超时比分、基地击毁。按 §5.6.1、§5.6.2、§5.8 编写临界、双方同时争夺和整局测试。
3. **P3：重装与经济闭环**。科技核心装配、难度升级、装配收益、42mm模块安装/解锁/发射条件及相关AI。
4. **P4：2027地形、场地与增益**。按图纸实现并验证碰撞、可达性、隧道与制高点等规则区域。
5. **P5：机库+4自主空中机器人**。合法出库、动作、冲击结算（待定值明确标注为仿真假设）。
6. **P6：自适应装甲、雷达/飞镖、能量机关、哨兵、处罚、全部经济和后勤**。逐条回填覆盖矩阵。
7. **P7：端到端AI和观战**。固定种子无界面420秒/60Hz、跨独立进程一致；HUD/视觉消费真实规则状态，不能反向裁判。
8. **合并条件**：PR单一目标、测试覆盖、必要视觉验证，合并后 main 的 Linux Tests、Windows build、macOS build均成功，记录SHA。

## P2c 控制度与胜负结算实施记录

P2c 完成 §5.6.2 控制度和 §5.8 胜负结算，并通过现有 `Match.update`、`MatchResult`、战报和 seeded replay 生效：

| 条款/机制 | 实现与自动化验证 | 边界 |
| --- | --- | --- |
| §5.6.2 前哨阵地控制度 | 两处前哨均由同一队伍控制时每秒 +1；临时/完全控制都计入 | 条文使用已定义临时、完全两类状态后的通称“控制”；未要求“完全控制”。这也与对方仅可临时控制基地阵地但仍需按控制度计分相一致。按固定 Match tick 精确累计分数，HUD 展示整数已完成度数 |
| §5.6.2 基地阵地控制度 | 两处基地均由同一队伍控制时每秒 +3 | 包含临时和完全控制；领土状态变化在 Match tick 边界生效 |
| §5.8 基地击毁 | 真实 17mm 哨兵弹丸击毁基地后按双方剩余基地 HP 结算，早于时间结算 | 同一 Match tick 内双方基地若同为 0 HP，则此优先级同值判平局 |
| §5.8 420 秒顺序 | 控制度 → 全队实际攻击伤害 → 全队地面机器人剩余 HP → 平局 | 比较的是 RuleSet 累计的控制度/Match 伤害事件/机器人 HP；未把结构 HP 混入“全队机器人剩余 HP” |
| 回放与复位 | 结束时沿用 `MatchResult`、战报 `winner_id`、记录及校验 | reset 清零控制度与伤害计数；不再写入 `unsettled-timebox` |

控制度用于胜负比较时保留精确分数，兼容既有显示协议时只显示已完成整数度数。自动化测试覆盖真实占点 tick 的临时控制积分、逐级结算优先级、真实 Match 伤害事件、基地弹丸击毁、平局、reset 和 420 秒 seeded replay。
