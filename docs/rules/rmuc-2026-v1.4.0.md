# RMUC 2026 Regional V1.4.0 Rules Lab

This document records the audited baseline implemented by RuleSet
`rmuc-2026-region-v1.4.0`. It is intentionally a partial implementation and
must coexist with future national-stage RuleSets such as
`rmuc-2026-national-v2.1.0`; later manuals must not overwrite this identity.

## Source identity

- Competition: RMUC
- Season: 2026
- Stage: regional
- Official version: V1.4.0
- Manual release: 2026-03-20
- Status in this repository: `official-partial`
- Official rules/resources archive:
  https://bbs.robomaster.com/wiki/20204847/809871?source=7

The regional V1.4.0 manual defines a seven-minute match. The formal roster is:

- Hero ×1
- Engineer ×1
- Infantry ×2
- Drone ×1
- Sentry ×1
- Dart System ×1
- Radar ×1

This Rules Lab slice creates only the ground/mobile and damageable-structure
subset:

- Hero ×1 per team
- Engineer ×1 per team
- Infantry ×2 per team
- Sentry ×1 per team
- Base ×1 per team
- Outpost ×1 per team

Drone, Radar, and Dart System are not instantiated.

## Damageable structures

Core now has a deliberately small stationary `Structure` data object. Robot
remains the only moving/attacking entity. `Match` keeps `robots` and
`structures` as separate collections; pathfinding, movement, collision
resolution, and AI iteration remain robot-only.

The V1.4.0 structure HP used by this RuleSet is:

| Structure | Max HP |
| --- | ---: |
| Base | 5000 |
| Outpost | 1500 |

Scenario YAML contains only structure identity, side, and position. Structure HP
comes from the RuleSet.

## Base and Outpost lifecycle

While a team's Outpost is alive, that team's Base cannot receive attack damage
and is excluded from RMUC target candidates. Once the Outpost is destroyed, the
Base becomes damageable.

When Base HP is at or below 2000, the RuleSet records
`base_armor_deployed = True`. This is state/HUD only: the current simulator has
no armor hitboxes or facing model.

An Outpost destruction records the historical fact
`outpost_ever_destroyed = True`. Rebuilding the Outpost never clears this
history.

## Rebuild opportunities

For every cumulative 1000 HP actually lost by a Base, its team gains one
stackable Outpost rebuild opportunity. Thresholds are settled from actual HP
loss, so one large damage event can cross multiple thresholds.

A rebuild is eligible only when:

- the Outpost is currently destroyed;
- at least one rebuild opportunity is available;
- the rebuild happens within the first 300 seconds of the match; and
- a living friendly Hero, Engineer, Infantry, or Sentry continuously occupies
  that team's rebuild zone.

Continuous occupation duration is per robot:

| Robot | Required continuous occupation |
| --- | ---: |
| Engineer | 5 s |
| Hero | 10 s |
| Infantry | 10 s |
| Sentry | 10 s |

Progress is stored independently by robot. Leaving the zone clears only that
robot's progress. Progress from different robots is never combined.

Completing a rebuild:

- sets the Outpost alive;
- restores it to 750 HP;
- consumes exactly one rebuild opportunity;
- clears all rebuild progress; and
- restores Base invincibility because the Outpost is alive again.

Any incomplete progress is cleared at the 300-second cutoff. Time after the
cutoff never contributes to a rebuild.

## Combat approximation

Attackers are always Robots. Legal targets may be Robots or Structures.

Target selection is deterministic: alive enemy targets within range and LOS are
ordered by distance, then id. The RuleSet supplies a separate `can_target`
gate so RMUC can exclude an invincible Base without changing RMUL's existing
"invincible robot can still absorb attack intent" behavior.

This slice still uses synthetic direct damage, not entity projectile physics or
armor-module hit detection:

- committed 17 mm attack intent → nominal 20 HP direct damage;
- committed 42 mm attack intent → nominal 200 HP direct damage.

Actual HP loss, not nominal damage, is recorded as team attack damage. Damage to
enemy Robots, Bases, and Outposts all contributes.

Engineer is a mobile ground Robot with no launcher in this slice. Its fixed rule
metadata includes 250 HP and a 120 W chassis power limit; Tech Core and Energy
Unit mechanics are not implemented.

The Rules Lab uses the V1.4.0 default/level-1 or fixed values where this slice
needs an initial HP profile, but Experience and Performance progression are not
implemented. Movement speed, attack range, attack interval, and direct-damage
resolution remain Rules Lab abstractions.

## Match result

The RMUC time limit is 420 seconds. Result evaluation starts when time expires or
when either Base is destroyed.

The implemented V1.4.0 single-match ordering is:

1. Compare remaining Base HP; higher wins.
2. If Base HP is tied and neither Outpost has ever been destroyed, compare
   current Outpost HP.
3. If Base HP is tied and exactly one Outpost has ever been destroyed, the team
   whose Outpost has never been destroyed wins.
4. If still unresolved, compare team attack damage.
5. If still unresolved, compare total remaining Robot HP only.
6. If still tied, draw.

Base and Outpost HP are not counted again in the final Robot-HP tiebreak.

## Synthetic field boundary

The RMUC Rules Lab world is 2800 × 1500 units, using 100 world units = 1 m. This
round does not claim an official 28 m × 15 m field reconstruction.

Only these semantic areas/objects are placed:

- two start areas;
- two Bases;
- two Outposts;
- two Outpost rebuild zones.

All internal coordinates and rectangular footprints are explicit synthetic Rules
Lab approximations. The existing generic Viewport is reused unchanged.
