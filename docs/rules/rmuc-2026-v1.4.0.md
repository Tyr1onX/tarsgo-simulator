# RMUC 2026 Regional V1.4.0 Rules Lab

This document records the audited baseline implemented by RuleSet
`rmuc-2026-region-v1.4.0`. It is intentionally partial and must coexist with
future national-stage RuleSets rather than being overwritten by later manuals.

## Source identity

- Competition: RMUC
- Season: 2026
- Stage: regional
- Official version: V1.4.0
- Status in this repository: `official-partial`
- Primary rule baseline: V1.4.0 §5.4 Experience and Performance Systems,
  including Tables 5-13 through 5-17.
- V1.4.2 is used only as a cross-check where wording is unchanged; this
  RuleSet's identity remains V1.4.0.

The regional match lasts seven minutes. The formal roster contains Hero,
Engineer, Infantry ×2, Drone, Sentry, Dart System, and Radar. This Rules Lab
currently instantiates only Hero, Engineer, Infantry ×2, Sentry, Base, and
Outpost. Drone, Radar, and Dart System are not created.

## Experience System

Only Hero and Infantry participate in the current progression state. Engineer
and Sentry do not gain Experience. Future Drone progression is documented but
not instantiated because there is no Drone entity in this slice.

Progression belongs to `RMUC2026RegionalRules`, not to the generic `Robot`
model. Each eligible robot owns private rule state equivalent to:

```text
experience: float
level: int
```

Experience uses `float` because the official system includes averaging and
one-decimal allocation paths that are intentionally deferred.

### Level thresholds

| Level | Experience |
| ---: | ---: |
| 1 | 0 |
| 2 | 550 |
| 3 | 1100 |
| 4 | 1650 |
| 5 | 2200 |
| 6 | 2750 |
| 7 | 3300 |
| 8 | 3850 |
| 9 | 4400 |
| 10 | 5000 |

All ten levels are stored and validated even though the current gameplay cap is
Lv5.

### Current level cap

Both teams start with `level_cap = 5`. Tech Core assembly is not implemented,
so there is no command or gameplay path that raises the cap in this round.

At Lv5, Experience is clamped exactly to 2200 and the robot stops gaining any
additional shot, damage, or kill Experience. It does not accumulate hidden XP
for a future instant upgrade. The per-team cap is rule state so a later Tech
Core slice can raise it to 7 and then 10 without changing the Experience model.

### Deterministic combat Experience sources

Known-source Experience is implemented using existing match facts.

- committed Hero attack intent: +10 XP;
- committed Infantry attack intent: +1 XP;
- Robot actual HP damage: +4 XP per actual HP lost;
- Outpost actual HP damage: +2 XP per actual HP lost;
- Base actual HP damage: +1 XP per 2 HP, with odd actual damage rounded up;
- Robot destruction: kill Experience described below.

Sentry receives no personal Experience and Engineer has no launcher in this
slice. Team attack-damage accounting remains independent from personal
Experience.

Damage Experience always uses `event.damage`, which is the actual HP loss.
Therefore invincible Base attacks that resolve to zero damage generate no
damage Experience, and overkill awards Experience only for remaining HP.

### Kill Experience

For a known eligible attacker:

```text
if victim_level >= attacker_level:
    XP = 50 × victim_level × (1 + 0.2 × (victim_level - attacker_level))
else:
    XP = 50 × victim_level
```

Hero and Infantry victims use their current progression level. Engineer and
Sentry are treated as Lv1 for this calculation. Future Drone will use its
progression level once Drone exists.

Engineer and Sentry attackers do not gain Experience and their kill Experience
is not redistributed to teammates in this slice.

### Processing order

The simulator keeps the existing deterministic event order:

1. `on_attack_committed` grants shot XP when Combat commits a legal attack;
2. `ROBOT_DAMAGED` / `STRUCTURE_DAMAGED` grant actual-damage XP;
3. `ROBOT_DESTROYED` grants kill XP.

No event-system rewrite is introduced for edge cases around a single hit that
also crosses a level threshold.

Unknown-source / redistributed Experience is deferred because the current event
model intentionally does not classify projectile, penalty, Dart, or other
future damage-source taxonomies.

The following official Experience sources are also deferred until their owning
systems exist: Energy Mechanism interactions, Hero deployment-mode actions,
terrain traversal, Dart interactions, and Drone progression.

### Effective parameters

The RuleSet derives one minimal effective Performance view for each eligible
robot:

```text
max_hp
chassis_power_limit
heat_limit
cooling_per_second
```

Hero gets all four values from its selected whole-robot profile. Infantry gets
HP/Power from its selected chassis profile and Heat/Cooling from its selected
launcher profile.

Hero/Infantry initial `RobotParameters.max_hp` now comes from the selected Lv1
Performance table; the YAML no longer duplicates those max-HP or chassis-power
values under `lab_robot_parameters`. Engineer remains fixed at 250 HP / 120 W
metadata and Sentry remains fixed to this slice's existing parameters.

Only max HP affects gameplay in this round. Power, Heat Limit, and Cooling are
stored and exposed as effective rule parameters for later systems. RMUC heat
ticks, chassis buffer, and power-off behavior are explicitly not implemented.

### HP behavior on level-up

When an eligible living robot levels up, current HP increases only by the
increase in max HP.

Example, Hero long-range-priority:

```text
before: 100 / 150
Lv1 -> Lv2
after:  115 / 165
```

The robot does not heal to full. Current HP is capped at the new max HP. If a
dead eligible robot receives a synthetic/test level update, max HP may change
but `alive=False` and `hp=0` are preserved.

A single Experience grant may cross several thresholds; the final level and
Performance are applied directly while preserving the cumulative max-HP delta.

## Energy Unit and Tech Core D1-D3

The V1.4.0 Tech Core / Energy Unit mechanism is represented as RMUC RuleSet
state rather than as a new physical entity hierarchy. Engineer carries a
boolean Rules Lab resource state:

```text
carrying_energy_unit = True / False
```

This means only "the Engineer currently has the Energy Unit needed for one
Difficulty 1-3 assembly attempt." It does **not** claim that an Engineer can
physically carry only one Energy Unit. Real carried quantity and Difficulty 4's
dual-unit requirement are deferred.

### Synthetic Rules Lab zones

The scenario contains four additional rectangular semantic zones:

- `red-resource` / `blue-resource`;
- `red-assembly` / `blue-assembly`.

Their footprints and coordinates are synthetic approximations for training.
They are not an official field-coordinate reconstruction.

A living Engineer may pick up an Energy Unit only while inside its own resource
zone, while not already carrying one, and while the match is active. The
resource source is a **synthetic renewable rule source**: this slice does not
model official stock count, respawn, multiple physical units, or unit world
positions.

### Tech Core attempt state

Each team stores completion counts for Difficulty 1-3 and at most one active
attempt. An attempt records the Engineer, selected difficulty, and continuous
time outside the team's assembly zone.

Difficulty availability is:

| Difficulty | Available after | Prerequisite |
| ---: | ---: | --- |
| 1 | 0 s | none |
| 2 | 60 s | D1 completed at least once |
| 3 | 120 s | D2 completed at least once |

Time availability is necessary but not sufficient. For example, at 300 seconds,
D2 is still unavailable if D1 has never been completed. Difficulty 1-3 may all
be repeated after their prerequisites are satisfied. Difficulty 4 is
deliberately unsupported in this slice.

Starting an attempt additionally requires a living Engineer, a carried Energy
Unit, the Engineer inside its own assembly zone, and no currently active
attempt. Once an attempt starts, its difficulty cannot be switched.

### Mechanical assembly abstraction

This Rules Lab does not simulate Energy Unit insertion, 100 mm translation,
P/Q-axis rotation, pose, angle, lighting, sensor confirmation, or manipulator
physics.

**Mechanical assembly success is abstracted as an explicit Rules Lab
confirmation.**

The confirm action means that the real mechanical assembly steps are assumed to
have been successfully completed by the player/test. It is not a claim that a
real Tech Core succeeds unconditionally.

A valid confirmation requires the same Engineer to remain alive and inside its
own assembly zone. Success consumes the carried Energy Unit, clears the active
attempt, and increments that difficulty's completion count.

### Attempt failure

During an active attempt:

- inside the assembly zone resets `outside_zone_elapsed` to zero;
- outside the zone accumulates continuous time;
- reaching 15 continuous seconds outside fails the attempt;
- returning before 15 seconds resets the timer;
- destruction of the active Engineer immediately fails the attempt.

Failure clears the attempt and the carried Energy Unit, representing the rule
system recovering the unit.

If an Engineer is carrying an Energy Unit but has not started an attempt, this
Rules Lab also clears the carrying state when that Engineer is destroyed. This
is a **synthetic recovery simplification**, not an exact simulation of the
physical unit's official post-destruction state.

### First / repeat completion and level-cap rewards

The YAML records audited first/repeat reward metadata for D1-D3. This slice
consumes only the level-cap reward:

- D1 first/repeat: completion count only; periodic-gold metadata is stored but
  Economy is not implemented;
- D2 first completion: team level cap `5 → 7`;
- D2 repeat: count increases, cap remains unchanged;
- D3 first completion: team level cap `7 → 10`;
- D3 repeat: count increases, cap remains unchanged.

D3's defense-bonus metadata and all periodic-gold metadata are stored only as
rule data. There is no Reward Engine, Economy consumer, defensive modifier,
Base +2000 HP, or virtual shield in this slice.

Changing the cap does not grant Experience and does not directly change HP,
Power, Heat Limit, or Cooling. A Hero at `Lv5 / XP2200 / CAP5` remains
`Lv5 / XP2200` immediately after D2 unlocks CAP7. Only future Experience can
advance it to Lv6/Lv7. Experience discarded while capped is not reconstructed
or credited retroactively.

The existing per-team `_level_cap_by_team` remains the only level-cap source,
so the unlock applies naturally to all current and future progression-capable
robots on that team.

### Why Difficulty 4 is deferred

Difficulty 4 is not treated as a simple fourth integer difficulty. V1.4.0 adds
a separate coupled mechanism involving two Tech Cores, dual Energy Units,
per-step synchronization and timing, a 45-second overall window, cross-team
priority/interruption behavior, failure cooldown/lockout rules, special gold
penalties, and additional first-completion rewards including Base/defense
effects.

Those mechanics require their own Sprint. Calls requesting Difficulty 4 return
unsupported/false in this slice.

## Base and Outpost lifecycle

Base / Outpost behavior from the previous slice remains unchanged:

- Base: 5000 HP;
- Outpost: 1500 HP;
- a living Outpost makes its Base invincible;
- Base HP at or below 2000 records armor-deployed state;
- each cumulative 1000 Base HP lost grants one stackable Outpost rebuild
  opportunity;
- Engineer rebuild time: 5 s;
- Hero / Infantry / Sentry rebuild time: 10 s;
- rebuild is disabled at 300 s;
- rebuilt Outpost returns at 750 HP and restores Base invincibility;
- `outpost_ever_destroyed` remains true after rebuild.

## Combat approximation

Attackers remain Robots; legal targets may be Robots or Structures. The current
Rules Lab still uses synthetic direct damage rather than projectile physics or
armor-module hit detection:

- 17 mm committed attack intent → nominal 20 direct damage;
- 42 mm committed attack intent → nominal 200 direct damage.

Actual HP loss is used for team attack damage and for damage Experience.

## Match result

The RMUC time limit remains 420 seconds. On timeout or Base destruction, the
result chain remains:

1. remaining Base HP;
2. if neither Outpost was ever destroyed, current Outpost HP;
3. if exactly one Outpost was ever destroyed, the never-destroyed side;
4. team attack damage;
5. remaining Robot HP only;
6. draw.

## Synthetic field boundary

The Rules Lab world remains 2800 × 1500 units at 100 world units = 1 m. Start
areas, Base/Outpost placements, and rebuild-zone rectangles are synthetic
approximations rather than an official complete field reconstruction.
